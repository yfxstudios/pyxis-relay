# Carrier board rev A: KiCad project (schematic draft 1)

Open `relay.kicad_pro` in KiCad 10. **[relay.pdf](relay.pdf)** is the schematic as a PDF, 8 pages.

The schematic is **generated** from the Python files in `gen/`, one per sheet, so every connection is written down
next to the reason for it.

```bash
gen/check.sh        # regenerate, run KiCad's electrical rules check (ERC), print problems and every net
```

After editing a `gen/*.py` file, run it again; the `.kicad_sch` files are overwritten. If you'd rather edit in
KiCad's editor from here on, that's fine too: stop using the generator, since a regenerate would undo those edits.

**Status:**
- ERC passes with one warning: the M.2 socket footprint isn't made yet.
- 191 parts.
- Every RK628D ball (144) is assigned and checked against the datasheet ball map.
- Every Radxa CM3 pin (300) is assigned or marked unused; the build fails if one is missed or used twice.

## Before this can become a board

1. **Check the module connectors:**
   - Compare our three DF40 receptacles with Radxa's IO-board connector data
     (`../datasheets/radxa_cm3_io_board_b2b_connector_20230718.asc`): pin 1 orientation, the spacing between
     connectors, and the M2.5 mounting holes.
   - J68's pads are Radxa pins 101–200 minus 100; check that against the IO board too.
2. **Footprints still to make or confirm:**
   - **M.2 E-key socket:** for the chosen part.
   - **Gigabit magjack:** pick an LCSC part with the Pulse JK0654219 pinout, or redo that footprint.
   - **HDMI connector:** the bought LCSC part (C2902698) vs. the Molex footprint used now.
   - **RK628D:** check the generated 0.65 mm BGA footprint (`relay.pretty/`) against the datasheet land pattern
     and JLCPCB's BGA rules.
   - **Locking DC jack:** pick it together with the case.
3. **Values to confirm:**
   - **Crystal load capacitors (18 pF):** match the chosen 24 MHz crystal's rated load capacitance.
   - **Inductor saturation currents.**
   - **The RK628D 1.1 V current:** for the Rockchip RK628D hardware design guide, which we don't have yet.
4. **Layout:** 4-layer impedance-controlled stack, rules in `../REV_A_SPEC.md` section 6, length limits from the
   Radxa CM3 datasheet.

## Board: first placement (Oct 22)

`relay.kicad_pcb` is generated by `gen/pcb.py` from the schematic netlist. Run it with KiCad's bundled Python:

```bash
/Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3 gen/pcb.py
```

Renders: [3D view](renders/rev_a_placement_3d.png), [top view](renders/rev_a_placement_top.png).

**What it sets up:**
- **Board:** 120 × 100 mm, 4 layers.
- **Front panel:** HDMI IN and HDMI OUT.
- **Back panel:** USB-C, DC, the NP-F lead and RJ45.
- **Net classes:** in `relay.kicad_pro`.

  | Class | Width / gap |
  |---|---|
  | 100 Ω differential (HDMI, CSI, Ethernet) | 0.10 / 0.10 mm |
  | 90 Ω differential (USB) | 0.12 / 0.10 mm |
  | 85 Ω differential (PCIe) | 0.14 / 0.10 mm |
  | Power | 0.5 mm |
  | Default | 0.127 mm |

  These are first estimates for JLCPCB's JLC04161H-3313 stackup. **Confirm each with JLCPCB's impedance
  calculator.**
- **Module connectors and mounting holes:** copied from Radxa's own CM3 IO board (`relay.pretty/Radxa_CM3_*`,
  from `../datasheets/radxa_cm3_io_board_b2b_connector_20230718.asc`). The three receptacles and the four M2.5
  holes share one origin, so their spacing matches Radxa's working board exactly. Radxa's pad rows are 2.66 mm
  apart, against 3.08 mm in KiCad's stock DF40 footprint, so ours copy Radxa's.

**Placement:**
- **The CM3** sits in the middle, turned so J68 (camera input, HDMI out, PCIe) faces the front.
- **The RK628D** is between HDMI IN and the CM3's camera pins, so that run is short.
- **The M.2 Wi-Fi socket** is on the left, with the card lying over the board.
- **Power** is along the back-left; the SDI header (not fitted) is on the right.
- **Small parts** are packed by sheet into regions near their main chip (`REGIONS` in `gen/pcb.py`).

**DRC:** no clearance, short or overlap errors. What remains:
- **499 unrouted connections:** routing is next.
- **Labels overlapping:** cosmetic.
- **Edge connectors at the board edge:** expected; they sit at or slightly past it.

**Next, in order:**
1. **Hand placement:**
   - Every decoupling capacitor at its pin: the RK628D's 1.1 V and 3.3 V balls, the module's 5 V pins.
   - Each converter as a tight loop: input capacitor, switch node, inductor, output capacitor.
   - Crystals next to their chips.
   - ESD arrays at the connectors.
2. **Route the critical signals first:**
   - CSI from the RK628D to J68.
   - HDMI IN to the RK628D, and J68 to HDMI OUT.
   - PCIe to the M.2 socket; USB.
   - The Ethernet pairs from J69 to the RJ45.
   - Then power, a solid ground on L2, power on L3.
3. **Before ordering:**
   - Replace the M.2 placeholder footprint with the chosen socket's land pattern.
   - Confirm the HDMI, RJ45 (gigabit, JK0654219 pinout) and DC-jack footprints against the bought parts.
   - Fit the board size to the case.


- `relay.kicad_sch`: root sheet; one `.kicad_sch` per sheet.
- `relay.kicad_sym` and `relay.pretty/`: project symbols and footprints, also generated.
- `erc.json`, `build.net`: output of the last `gen/check.sh`.
